# Phase 07 — UI Design Contract

> Visual and interaction contract for Phase 7 (UI-01, UI-02, DATA-03; also renders DATA-02 provenance and the AGENT-03 approval gate). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Stack (locked, from the scaffold and CLAUDE.md): SvelteKit 2 + Svelte 5 runes, Tailwind v4 (`@tailwindcss/vite`, forms + typography plugins), adapter-static on Pages/HF with `BASE_PATH`, adapter-vercel on Vercel. **No component library.** Budget: 45 min across plans 07-01/07-02/07-03. Sections marked **[compressible]** can be cut first.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Svelte project; the shadcn gate does not apply. CLAUDE.md says no component library) |
| Preset | not applicable |
| Component library | none (hand-rolled Svelte 5 components + Tailwind v4 utilities) |
| Icon library | none. Unicode glyphs inside `<span aria-hidden="true">` (see Status Semantics). No icon package installed. |
| Font | Tailwind default `font-sans` (system UI stack) for all text. `font-mono` (Tailwind default stack) only for: warning codes, tool/op names, idempotency keys, requirement ids, payload JSON, the profile JSON editor, commit SHA. No webfonts. |
| Theme | Light + dark through `prefers-color-scheme` only (no toggle). Semantic CSS variables exposed as Tailwind colors through `@theme inline` (exact block below). |

### Non-negotiable platform rules (from vite.config.ts, deploy-pages.yml, 01-01-SUMMARY)

1. **Every internal link and every static fetch is prefixed with `base` from `$app/paths`.** Examples: `href="{base}/evals/"`, `fetch(`${base}/data/evals.json`)`. A hard-coded `/evals` or `/data/...` breaks GitHub Pages (`/multi-app-agent`). Hash links (`#plan`) don't need the prefix.
2. Add `export const trailingSlash = 'always';` to `web/src/routes/+layout.ts`, next to the existing `prerender = true`. The build then emits `evals/index.html`, which resolves on Pages, the HF static Space and Vercel. Write internal links with the trailing slash: `{base}/`, `{base}/evals/`.
3. `web/static/.nojekyll` already exists. Don't remove it.
4. `src/lib/core/**` stays framework-free (boundary.test.ts). UI helpers go in `src/lib/ui/**` and components in `src/lib/components/**`. Both may import core through relative paths or `$lib/core/...`.
5. Core is clock-free. The UI injects `today`: `new Date().toLocaleDateString('en-CA')` gives the local date as `YYYY-MM-DD`, which is passed to `analyzeGaps(profile, dataset, { today })`.
6. Format date-only strings (`2026-11-30`) with `Intl.DateTimeFormat('en-US', { month: 'short', day: 'numeric', year: 'numeric', timeZone: 'UTC' })` so they don't shift by a day.

## Spacing Scale

Declared values (multiples of 4; these match Tailwind's default 0.25rem step):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Glyph-to-label gap inside chips, chip vertical padding (`py-1`) |
| sm | 8px | `2` | Chip horizontal padding (`px-2`), gaps between chips and inline row items, list row gap |
| md | 16px | `4` | Card padding on mobile (`p-4`), stack spacing inside cards (`space-y-4`), grid gap for stat cards, page gutter on mobile (`px-4`) |
| lg | 24px | `6` | Card padding at `sm:` and up (`sm:p-6`), main two-column grid gap (`gap-6`), page gutter at `sm:` (`sm:px-6`) |

| 2xl | 48px | `12` | Vertical gap between numbered sprint steps and between dashboard sections (`space-y-12`) |

Exceptions:
- Interactive rows and buttons are at least **44px** tall (`min-h-11`). This covers every checkbox label row, button, replay control and nav link.

- The header is 56px tall (`h-14`).
- Borders are 1px (`border`). The active nav indicator is 2px (`border-b-2`). Focus outline is 2px with a 2px offset.
- Horizontal bars in the eval table and taxonomy are 8px tall (`h-2`).

## Typography

Exactly 4 sizes and 2 weights. Each maps to a default Tailwind v4 class, which brings its paired line height.

| Role | Size | Weight | Line Height | Tailwind | Used for |
|------|------|--------|-------------|----------|----------|
| Body | 16px | 400 | 1.5 (24px) | `text-base` | Paragraphs, warning messages, action summaries, form inputs, banner text |
| Label | 14px | 400 (600 for chip labels and table headers) | 1.43 (20px) | `text-sm` | Chips, badges, field labels, table cells, trace rows, source links, meta lines, mono codes, payload JSON |
| Heading | 20px | 600 | 1.4 (28px) | `text-xl font-semibold` | Section headings (h2 "2. Gap report"), school name in gap cards (h3), dashboard section headings |
| Display | 24px | 600 | 1.33 (32px) | `text-2xl font-semibold` | Page H1 ("Application sprint", "Eval results") and the headline stat numbers |

Weights: **400** (`font-normal`) and **600** (`font-semibold`) only. Don't use `font-bold` or `font-medium`.
Numbers in stat cards, the trace and tables use `tabular-nums`.
Prose from the dataset (essay prompts) uses Body. The typography plugin is **not** used on these pages.

## Status Semantics (never color-only)

Every status renders with `StatusChip.svelte`:

`<span class="inline-flex items-center gap-1 rounded-md border px-2 py-1 text-sm font-semibold {tokens}"><span aria-hidden="true">{glyph}</span>{label}</span>`

The visible **label text** carries the meaning. The glyph is decorative and the color is a third, redundant cue. The single map lives in `web/src/lib/ui/status.ts` (`STATUS: Record<StatusKey, { token, glyph, label }>`).

### Trace step (display status)

| Display status | Token | Glyph | Label |
|----------------|-------|-------|-------|
| `queued` | idle | `○` | Queued |
| `running` | idle | `…` | Running |
| `ok` | ok | `✓` | OK |
| `retried` | warn | `↻` | Retried ×{attempts} (the op ended OK after more than one attempt) |
| `deduped` | info | `=` | Deduped |
| `blocked` | block | `⊘` | Blocked |
| `failed` | fail | `✕` | Failed |

Mapping from the existing `TraceEvent` (`schemas.ts`, `TraceStatus = ok | error | deduped | skipped`) lives in `web/src/lib/ui/trace-rows.ts`:
- `status === 'deduped'` → `deduped`
- `status === 'skipped'` and `attrs.reason` in `['not_approved', 'policy', 'allowlist', 'injection']` → `blocked`. Any other `skipped` → row omitted.
- `status === 'error'` → `failed`
- `status === 'ok'` and `Number(attrs.attempt) > 1` → `retried`
- `status === 'ok'` → `ok`
- A span `start` with no matching `end` yet → `running`

### Mode detection (static showcase vs live)

`web/src/lib/ui/mode.svelte.ts` exports a `$state` `mode: 'detecting' | 'live' | 'replay'` and `detectMode()`:
- If `page.url.searchParams.has('replay')`, set `replay` (demo fallback override).
- Otherwise `fetch(`${base}/api/health`)` with a 1500 ms `AbortController` timeout. `live` only if `res.ok`, content-type contains `application/json`, and `body.target === 'vercel'`. Anything else (404 HTML on Pages/HF, network error, timeout) → `replay`.
- While `detecting`, the header pill reads "Checking…" (idle) and step CTAs stay disabled. Gap analysis still works because it runs client-side.

Sprint data comes through one interface, so Phase 9 only adds a second implementation:

```ts
// web/src/lib/ui/sprint-source.ts
interface SprintSource {
  kind: 'live' | 'replay';
  buildPlan(profile: Profile): Promise<{ plan: Plan; preflight?: Record<string, 'new' | 'exists'> }>;
  execute(plan: Plan, approvedIds: string[], onEvent: (e: TraceEvent) => void): Promise<RunReport>;
  rerun?(): Promise<{ events: TraceEvent[]; report: RunReport }>;
}
```

`ReplaySource` is built in Phase 7. `LiveSource` (`/api/plan` + `/api/execute` SSE) comes in Phase 9. Replay semantics:
- `buildPlan` returns the recorded plan.
- `execute` emits the recorded events whose `attrs.actionId` is approved, one visible row every **400 ms**.
- Unapproved actions produce no trace rows. They appear in the final panel as `skipped` ("Not approved").

**Static recording files** (written by 07-03 from `scripts/record.ts`, PII already redacted):
- `web/static/data/hero-run.json`: `{ recordedAt: ISO, commitSha: string, profileId: 'demo', plan: Plan, preflight?: Record<actionId,'new'|'exists'>, events: TraceEvent[], report: RunReport, rerun?: { events: TraceEvent[], report: RunReport } }`
- `web/static/data/silent-failure-run.json`: `{ recordedAt, commitSha, scenarioId, description, events: TraceEvent[], report: RunReport, oracle: { caught: boolean, failureClass: FailureClass | null, expected: string, found: string, stepSpanId: string } }`
- `web/static/data/evals.json`: produced by Phase 6 (see the Eval dashboard data contract).

Parse all three with zod `safeParse` in `web/src/lib/ui/data.ts` (`loadStatic<T>(path, schema)`). On a mismatch, show the error state and never render partially.

   - On Run, focus moves to the "4. Run trace" h2 (`tabindex="-1"`).
   - Focus is **not** moved when the run ends; the live region announces it instead.
   - After "Build plan", focus moves to the "3. Plan & approve" h2.
   - The visible focus ring is the global 2px accent outline and is never removed.
4. **Live regions:**
   - Trace: one `sr-only` `aria-live="polite" aria-atomic="true"` region with per-step terminal messages and the final summary (see Step 4).
   - Selection count and replay step counter are `aria-live="polite"`. The run status banner is `role="status"`.
   - Nothing uses `assertive`.
5. **Not color-only:** every status carries a visible text label (Status Semantics). Bars are `aria-hidden` and always sit next to a numeric percentage or count.
6. **Forms:** every input has a `<label>`. Errors use `aria-invalid` plus `aria-describedby` pointing at the error text id. The JSON textarea references the error list id. Number inputs use `inputmode="decimal"`.
7. **External links:** `target="_blank" rel="noopener noreferrer"` plus sr-only "(opens in new tab)". The `↗` glyph is `aria-hidden`.
8. **Tables:** `<caption>` (sr-only allowed), `<th scope="col">`, and the scenario name cell as `<th scope="row">`.
9. **Touch targets:** at least 44px (`min-h-11`) for buttons, nav links, checkbox rows and replay controls.
10. **Motion:** only `motion-safe:animate-pulse` (loading) and `motion-safe:transition-colors`. Replay pacing is a timer, not an animation, so it stays with reduced motion and the Step/Pause controls remain available.
11. **Contrast:** all token pairs above meet WCAG AA for 14px text in both schemes (fg/bg pairs listed are ≥ 4.5:1).
12. **Zoom and reflow:** usable at 400px width and at 200% zoom with no horizontal page scroll (only the table and `<pre>` scroll inside their containers).
